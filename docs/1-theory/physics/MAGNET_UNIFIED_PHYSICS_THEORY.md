## 1. Core Philosophy: Physics as Gate

MAGNET does not simulate reality for aesthetics; it validates physical existence to ensure that any design generated by an Agent can actually float, stay upright, and move as intended.

### 1.1 The Generative Thesis

MAGNET/CORTEX operates on a fundamental architectural principle:

> **Any valid vessel can be represented by composing universal geometry primitives. The kernel validates physics, not categories.**

This means:
- **No Enumeration:** The system never branches on `hull_type == "catamaran"` or `vessel_family == "patrol"`
- **Geometry-Derived:** All physical properties (displacement, stability, resistance) are computed from geometry primitives
- **Physics as Gate:** Hydrostatics validates physical reality; all else is advisory

### 1.2 Acknowledged Numerical Limitations

A physics stack earns trust by documenting its known limitations. We acknowledge the following in our implementation:
*   **Volumetric Drift:** Numerical integration via sections introduces ~0.1% drift compared to lofted NURBS surface. Engineering tradeoff for real-time performance.
*   **Spline Artifacts:** Cubic splines used for section interpolation may introduce small oscillations in areas of high curvature.
*   **Convergence Tolerance:** In the design spiral, we iterate until Displacement equals Weight within 2% (interactive) or 0.2% (engineering). Tighter tolerances cause oscillation and non-convergence.

### 1.3 The North Star Equation

```
Human Intent → LLM → Geometry Primitives → Validating Kernel → Validated Design
     │              │                              │
     │              │                              └── Physics truth
     │              └── Compositional language
     └── Natural language
```

### 1.4 Authority Hierarchy

| Layer | Responsibility | Examples |
|-------|---------------|----------|
| Human | "Is this a good design?" | Aesthetics, mission fit |
| Agent (LLM) | "Is this what the user wanted?" | Intent interpretation |
| Kernel | "Is this a valid physical object?" | Hydrostatics, stability |

### 1.5 The Seven Universal Primitives

All vessel geometry is composed from these primitives. Each primitive has a defined mathematical domain and degrees of freedom.

| Primitive | Definition | Physical Meaning |
|-----------|------------|------------------|
| `section` | 2D curve at longitudinal station | Hull cross-section shape |
| `surface` | Lofted 3D surface from sections | Hull shell |
| `body` | Watertight volume | Individual hull (mono/cat/tri) |
| `discontinuity` | Hard edge or chine | Flow separation line |
| `opening` | Penetration in surface | Sea chest, shaft exit |
| `flow_path` | Directed channel | Keel, skeg, tunnel |
| `attachment` | External addition | Appendage, fitting |

### 1.5.1 Mathematical Domains and Degrees of Freedom

| Primitive | Domain | DOF | Constraints |
|-----------|--------|-----|-------------|
| `section` | $S_i = \{(y_j, z_j)\}_{j=1}^{M}$ at $x = x_i$ | $2M$ (vertex positions) | Planar, closed polygon, CCW winding |
| `surface` | $\Sigma: [0, L] \times [0, 1] \to \mathbb{R}^3$ | $N \times M \times 2$ | Interpolated from sections, $C^1$ continuous |
| `body` | $B = \partial \Sigma$ (closed boundary) | Inherited from surface | Watertight (Euler $\chi = 2$), positive volume |
| `discontinuity` | $\gamma: [0, L] \to \mathbb{R}^2$ | $N$ (one per station) | Lies on surface, marks $C^0$ edge |
| `opening` | $O = \{(x, y, z, r)\}$ | 4 per opening | Center + radius, penetrates exactly one surface |
| `flow_path` | $P: [0, 1] \to \mathbb{R}^3$ | Variable (waypoints) | Directed, within or attached to body |
| `attachment` | $A = (B_{local}, T_{transform})$ | 6 + body DOF | Rigid transform $(R, t)$ applied to sub-body |

**Section Domain Specification:**
$$S_i: \mathbb{R} \to \mathbb{R}^2, \quad S_i(x_i) = \{(y_1, z_1), \ldots, (y_M, z_M)\}$$

Subject to:
- $z_1 = 0$ (keel on baseline) or $z_1 > 0$ (with explicit keel offset)
- $y_j \geq 0$ for half-sections (starboard), mirrored to port
- $z_M = z_{sheer}$ (sheerline height)

**Body Closure Constraint:**
A body $B$ is valid iff:
$$\oint_{\partial B} \vec{dA} = 0 \quad \text{(divergence theorem: closed surface)}$$

**Falsifiability:** If a standard industry hull cannot be represented within 1% volumetric accuracy using these primitives, the architecture fails.

## 2. Doctrine Lock (Non-Negotiable)

### 2.1 Gate vs Grade (Validity Classification)

- **Only Gate (Validity): Hydrostatics**
  - A design is **invalid** only if it cannot produce a physically coherent floating equilibrium (e.g., negative or zero displaced volume at solved draft, non-finite hydrostatics, or solver non-convergence).
- **Everything Else is a Grade**
  - **GM < 0 is NOT an invalid design.** It is a grade that triggers a high-severity warning and a suggested upstream fix.
  - Stability failures may halt *automatic iteration* but must return a structured result, not block the design from existing.
  - Resistance outside method envelopes is a grade (uncertainty flag), not a gate.

**Rationale:** If stability becomes a gate, novelty collapses into "safe families" by force.

### 2.2 Gate Execution Order (Non-Negotiable)

Gates execute in strict precedence order. If gate N fails, gates N+1... do not execute.

**1. Geometric Validation (Pre-Gate):**
- Section count ≥ minimum (21 for L > 10m)
- No self-intersection in sections
- No negative areas/volumes in underwater body
- **Return:** `INVALID_GEOMETRY` if failed

**2. Hydrostatic Gate (Primary Gate):**
- Can sections produce positive displaced volume at any draft?
- Can solver find equilibrium draft where Δ ≈ W?
- Are LCB, VCB, waterplane coefficients finite?
- **Return:** `INVALID_HYDROSTATIC` if failed

**3. Downstream Physics (Grades Only):**
- Stability: computes GM, GZ → returns `WARNING_SEVERE` if GM < 0, **never** `INVALID`
- Resistance: returns `UNSUPPORTED` if outside method envelopes, **never** `INVALID`
- All others: grades, diagnostics, warnings

**Rule:** Only Geometric Validation and Hydrostatics can block design existence.

### 2.2.1 Human Decision Point (Mandatory Halt)

**Problem:** If a design passes the Hydrostatic Gate but fails a severe Stability Grade, automated downstream processing (propeller sizing, arrangement) may waste compute on a design that requires revision.

**Solution:** Define an explicit **Human Decision Point** after Gate 2:

```
Gate 1: Geometry Validation     → PASS/INVALID
Gate 2: Hydrostatic Gate        → PASS/INVALID
                                     ↓
                              ┌──────────────────┐
                              │ HUMAN DECISION   │
                              │    POINT         │
                              └────────┬─────────┘
                                       │
            ┌──────────────────────────┼──────────────────────────┐
            ↓                          ↓                          ↓
    Grade: GM < 0              Grade: GM < 0.5m            Grade: All OK
    (SEVERE)                   (MEDIUM)
            │                          │                          │
            ↓                          ↓                          ↓
    HALT: Await Human          WARN: Continue with         AUTO: Continue
    Approval/Revision          Caution Flag                Downstream
```

**Halt Conditions:**
- `stability_grade == SEVERE` (GM < 0)
- `freeboard_grade == SEVERE` (deck awash)
- `convergence_status == NON_CONVERGENT`

**When Halted:**
1. System returns structured result with all computed values
2. System does NOT proceed to resistance, propulsion, or arrangement
3. System emits `awaiting_human_decision: true` flag
4. Human must explicitly approve continuation OR provide revision

**Human Approval Token:**
```json
{
  "decision": "CONTINUE_DESPITE_WARNING" | "REVISE",
  "approved_by": "user_id or session_token",
  "timestamp": "ISO8601",
  "rationale": "Intentionally testing unstable configuration",
  "acknowledged_risks": ["GM < 0 will capsize"]
}
```

**Rationale:** This prevents wasted computation while preserving the doctrine that unstable designs are valid physical objects. The human decides, not the kernel.

### 2.3 Convergence Tolerances (Unified)

Define two modes with explicit tolerances:

| Tolerance | Interactive Mode | Engineering Mode |
|-----------|-----------------|------------------|
| Displacement Balance | \|Δ - W\| / Δ < 0.02 (2%) | \|Δ - W\| / Δ < 0.002 (0.2%) |
| Draft Solving | 0.005 m | 0.001 m |
| Volumetric Change Stop | 1e-3 m³ | 1e-4 m³ |

The system **must declare which mode it used** in output metadata (`tolerance_mode: "interactive" | "engineering"`).

### 2.4 Alternative A: Geometry-Only Doctrine

MAGNET adopts **Alternative A (strict geometry-only)** as its foundational constraint:

> **There is only one authority: geometry. Everything else is measurement.**

This means:
- No regime selection that changes solver semantics
- No method switching based on hull type or category
- If a quantity cannot be computed as a continuous functional of geometry and operating state, it is not allowed to decide anything
- Fn, deadrise, and other proxies may be **reported**, never **consulted** for branching

**What this forbids explicitly:**
- Any `if` that changes solver behavior based on a dimensionless number
- Any default that exists "until better data is available"
- Any method whose validity depends on vessel category, even implicitly
- Any geometry mutation performed to "make physics work"
- Adding a new "type" enum to make physics work (declared failure condition)

**What Alternative A requires:**
- Resistance must be a continuous mapping from `(geometry, speed) → force`
- If multiple models exist, they must be blended as continuous functions, not selected
- If you cannot blend a method smoothly, you are not allowed to use it
- Legacy formulas must bend to geometry or be demoted to diagnostics

**The Quiet Consequence:**
Alternative A forces the system to tell the truth early. It will produce "bad" boats that are physically valid. It will refuse to tell users what they want to hear. It will surface instability instead of hiding it.

### 2.5 External Context for Compliance (Non-Geometric Input)

**Problem:** Regulatory compliance (IMO, classification societies) requires vessel categorization (cargo, passenger, fishing, etc.), but geometry-only doctrine forbids deriving this from hull shape.

**Solution:** Accept `compliance_context` as **external input** (not derived, not authoritative for physics):

```json
{
  "vessel_type": "cargo" | "passenger" | "fishing" | null,
  "regulation": "IMO_2008" | "MSC_267" | null,
  "flag_state": "string" | null
}
```

**Usage Rules:**
- Physics solvers (hydrostatics, stability) **never consult** this field
- GZ curve computation is context-free
- Compliance **reporting** (e.g., "meets IMO passenger ship criteria") **may consult** this field
- If context is null, system reports: "GZ curve computed, regulatory compliance cannot be assessed without vessel_type"

**Boundary:** This does not violate geometry-only doctrine because:
- It does not change physics outputs (GZ curve is identical regardless of vessel_type)
- It only affects **pass/fail grading** against external standards
- It is **user-declared**, not inferred by system

## 3. The Canonical Representation

A vessel's physical state is defined by a finite set of $N$ transverse sectional polygons $\{S_1, S_2, \ldots, S_N\}$. Each polygon $S_i$ must satisfy the following constraints:

### 3.0.1 Formal Constraints

**Planarity:** All vertices $(y_j, z_j)$ of section $S_i$ must lie on a plane $P_i$ at longitudinal coordinate $x_i$.

**Orthogonality:** The plane $P_i$ must be perpendicular to the longitudinal axis $X$. Mathematically: $\hat{n}_{P_i} \cdot \hat{X} = 1$.

**Winding:** Vertices must be ordered counter-clockwise when viewed from the positive $X$ direction (looking aft to forward) to ensure consistent normal vectors for volume calculation via Green's theorem.

**Closure:** Each polygon must be closed: the last vertex connects to the first.

**Numerical Enforcement:** Any calculation of displacement ($\nabla$), centers ($LCB$, $VCB$), or inertia ($I_t$, $I_l$) must use **Green's Theorem** on each polygon $S_i$ followed by longitudinal integration using **Simpson's 1/3 Rule** (or trapezoidal rule with Richardson extrapolation).

### 3.0.2 Authority Hierarchy

1. **The Section Set (Canonical):** The 2D station polygons are the mathematical authority for all hydrostatic, stability, and volume calculations. If the mesh and the sections disagree, the sections win.
2. **The Triangle Mesh (Derived):** The mesh is a post-hoc tessellation used for WebGL rendering and export (GLB/STEP). It holds no computational authority.

**Rule:** Solvers MUST consume the section representation to ensure path-independence.

### 3.1 Canonical Representation Contract

- **Canonical geometry = Section Set** (stations + points + explicit transforms)
- **Mesh is a derived artifact** and may be used only for:
  - Visualization and export (WebGL, GLB, STEP)
  - Diagnostics (watertightness, self-intersection detection)
  - *Cross-checking* volume (must never override sections)

### 3.2 Diagnostic Cross-Check Rule

If mesh-volume and section-volume disagree by > 1.0%:
- Return `DIAGNOSTIC_MISMATCH` with both values and likely causes (resolution, cap closure, transforms)
- **Do not "fix" geometry automatically**
- Log discrepancy for audit trail

### 3.3 What Mesh Cannot Decide

The following quantities must **never** be computed from mesh as authority:
- Displaced volume (hydrostatics)
- Wetted surface area for resistance (must derive from sections or flag as approximate)
- Waterplane properties (Aw, LCF, Iₜ)
- Stability metrics (GM, GZ)

If a future estimator requires mesh-only properties, it must be labeled `DIAGNOSTIC_ONLY` and cannot override section-derived values.

### 3.4 The Synchronization Scar

Discrepancies between Section-derived volume and Mesh-derived volume are expected (typically <0.5%). The system acknowledges this "bleed" and always defers to the Section Set for the legal load line.

## 4. Resolution Levels and Convergence

The system operates in two discrete resolution levels with explicit numerical specifications.

### 4.0 Resolution Level Definitions

| Parameter | Level 1 (L1 - Interactive) | Level 2 (L2 - Engineering) |
|-----------|---------------------------|---------------------------|
| Stations $N$ | $N \geq 21$ | $N \geq 41$ |
| Vertices per polygon $M$ | $M \geq 32$ | $M \geq 64$ |
| Convergence threshold $\epsilon$ | $\epsilon = 0.02$ (2%) | $\epsilon = 0.002$ (0.2%) |
| Max iterations | 25 | 50 |

### 4.1 Convergence Criteria (Formal)

An iteration is considered **converged** if and only if the Mass Residual ($Res_\Delta$) and Trim Residual ($Res_\tau$) are both less than $\epsilon$:

$$Res_\Delta = \frac{|\rho g \nabla - W|}{W} < \epsilon$$

$$Res_\tau = \frac{|LCB - LCG|}{L_{wl}} < \epsilon$$

**Convergence Rule:** Both conditions must be satisfied simultaneously:

$$\max(Res_\Delta, Res_\tau) < \epsilon$$

**Divergence Detection:**
- If volume oscillates with period > 3 iterations and amplitude > 0.1% V: return `NON_CONVERGENT`
- If max iterations reached without meeting $\epsilon$: return `CONVERGENCE_TIMEOUT` with best achieved result
- The kernel must halt and return `NON_CONVERGENCE` error if $\epsilon$ is not reached within the iteration limit

### 4.2 Resolution Level Selection

**L1 (Interactive):** Used during real-time drafting, slider adjustments, and conversational design. Prioritizes latency over precision.

**L2 (Engineering):** Used for final validation, export, regulatory compliance checks, and design commitment. Prioritizes precision.

**Automatic Escalation:** The system may auto-escalate from L1 to L2 when:
- User requests "validate" or "export"
- L1 results differ from L2 preview by > 5%
- Design approaches a regulatory threshold

### 4.3 Resolution Refinement Criteria

**Transverse Resolution (within level):**
- **Baseline:** $M$ points per section as specified by level
- **Adaptive Criteria:**
  - If max curvature $\kappa > 0.5$ m⁻¹: increase to $2M$ points
  - If hard chine detected (slope discontinuity): place 4 points within 10cm of chine
  - If multi-hull (gap > 2m): allocate points proportional to wetted perimeter per demihull

**Longitudinal Resolution:**
- **Baseline:** 21 stations for L < 30m, 41 stations for L > 30m
- **Adaptive Criteria:**
  - If LCB shift > 5% L over one station spacing: double local density
  - If section area changes > 20% per meter: halve station spacing locally

**Symmetry:**
- If hull is perfectly symmetric, represent as "half-section" with mirror transform
- Prevents floating-point asymmetry poisoning results

**Quality Metric:**
- After resampling, compare section-integrated volume to high-res reference (if available)
- If error > 0.5%, flag `RESOLUTION_INADEQUATE` and recommend refinement

### 4.3 Low-Latency Resolution Mode (Real-Time Window)

**Problem:** The "boat window" in the chatbot interface must update in real-time during LLM drafting. Full engineering-mode integration (21+ stations, 32+ points) introduces latency that breaks the conversational feel.

**Solution:** Define a coarsened "Drafting Mode" for rapid feedback:

| Mode | Stations | Points/Section | Typical Latency | Use Case |
|------|----------|----------------|-----------------|----------|
| **Drafting** | 12 | 16 | < 50ms | LLM typing, real-time preview |
| **Interactive** | 21 | 32 | < 200ms | User adjustment, slider interaction |
| **Engineering** | 41 | 64 | < 2000ms | Final validation, export |

**Drafting Mode Constraints:**
- **Volume Accuracy:** ±2% vs Engineering (acceptable for preview)
- **GM Accuracy:** ±10% (sufficient for "green/yellow/red" indicator)
- **Resistance:** Not computed (too inaccurate at low resolution)

**Auto-Escalation Protocol:**
```python
def compute_with_auto_escalation(hull, intent: str) -> PhysicsResult:
    """Start fast, escalate when precision matters."""

    # Phase 1: Drafting mode for instant feedback
    result_draft = compute_hydrostatics(hull, mode="drafting")

    if intent == "preview_only":
        return result_draft.with_flag("resolution_mode: drafting")

    # Phase 2: If user pauses typing (>500ms), escalate to interactive
    result_interactive = compute_hydrostatics(hull, mode="interactive")

    if result_interactive.differs_significantly(result_draft):
        # Warn: drafting preview was misleading
        emit_warning("Preview refinement: GM changed from {draft} to {interactive}")

    # Phase 3: On "validate" or "export", escalate to engineering
    if intent in ["validate", "export", "commit"]:
        result_engineering = compute_full_physics(hull, mode="engineering")
        return result_engineering

    return result_interactive
```

**UI Indicator Contract:**
- Drafting mode results must display with visual indicator (e.g., dashed outline, "~" prefix)
- User must not be able to export or commit from drafting mode
- Transition to engineering mode must be explicit user action or automatic on idle

## 5. Dimensional Circularity (Observations vs. Causes)

In many legacy systems, coefficients like `Cb` (Block Coefficient) are inputs that decide the hull shape. **In MAGNET, this is forbidden.**

*   **Coefficients are Observations:** `Cb`, `Cp`, and `Cm` are outputs derived from the geometry.
*   **Intent is the Cause:** The LLM may request a "high-speed displacement hull," which the geometry generator interprets by moving volume, but the final `Cp` is computed by the kernel from the resulting sections.
*   **Honesty Check:** If a solver (e.g., Holtrop-Mennen) receives a `Cp` that it did not derive itself, it must flag a "Causal Mismatch" error.

## 6. Allowed Proxies (and the Rule Against Hidden Enums)

Proxies derived from geometry and operating point are allowed:
- Fn (Froude number), Rn (Reynolds number)
- L/B, B/T (length/beam ratios)
- Deadrise(x) (at any station)
- Cp, Cb, Cm (all computed from canonical sections)

### 6.1 Proxy Rules

1. **Proxies may limit method validity** (produce warnings/uncertainty), **not design validity**
2. **No hard regime switches without continuity:**
   - If two methods exist, blend outputs smoothly across an overlap band and emit method weights
   - Transition bands must be defined and documented
3. **Every method output must carry:**
   - `validity_envelope`: why it applies (e.g., "Fn in [0.1, 0.45]")
   - `uncertainty_level`: LOW / MED / HIGH
   - `selection_weights`: e.g., `{holtrop: 0.7, savitsky: 0.3}`

### 6.2 Forbidden Patterns

- `if Fn < a: use_method_X else: use_method_Y` **without blending + disclosure**
- Any proxy threshold that changes kernel behavior silently
- Using proxies to infer "hull type" and then branch on type
- Regime switches that affect gradients discontinuously (agent trap)

### 6.3 Continuous Parameter-Space Weighting for Resistance

**DOCTRINE:** The kernel does not recognize vessel "types" or "regimes." Categorical terms ("Planing," "Displacement," "Semi-displacement") are **redacted** from all internal logic. Resistance calculations are treated as **Continuous Gradient Grades** over parameter space.

### 6.3.1 Froude Number Envelopes (Replacing Regime Language)

| Old Term (REDACTED) | New Specification | Fn Range |
|---------------------|-------------------|----------|
| ~~Displacement~~ | Low Froude Number Envelope | $Fn < 0.35$ |
| ~~Semi-displacement~~ | Transition Envelope | $0.35 \leq Fn < 0.50$ |
| ~~Planing~~ | High Froude Number Envelope | $Fn \geq 0.50$ |

**Envelope Restriction:** Empirical methods (e.g., Holtrop-Mennen, Savitsky) are bounded by their validated ranges of:
- Froude Number: $Fn = V / \sqrt{gL}$
- Slenderness: $L/\nabla^{1/3}$
- Prismatic Coefficient: $C_p$

### 6.3.2 Blending Logic (C² Continuous)

When a geometry exists in a transition zone (e.g., $0.35 < Fn < 0.50$), the result $R_{total}$ must be a weighted average using a $C^2$ continuous transition function:

$$w_m(Fn) = \frac{1}{2}\left[1 + \tanh\left(\frac{Fn - Fn_m}{\sigma_m}\right)\right]$$

where $Fn_m$ is the method center and $\sigma_m$ is the transition width.

**Blended Resistance:**
$$R_{total} = \frac{\sum_m w_m(Fn) \cdot R_m}{\sum_m w_m(Fn)}$$

**All method selection logic must be disclosed:**
```json
{
  "resistance_kN": 125.3,
  "method_weights": {"holtrop": 0.73, "savitsky": 0.27},
  "validity": {"holtrop": "NOMINAL", "savitsky": "EXTRAPOLATED"},
  "uncertainty": "MEDIUM",
  "Fn": 0.42,
  "envelope": "TRANSITION"
}
```

### 6.3.3 Gap Handling

If no method covers an operating point (total weight below threshold):
```json
{
  "status": "UNSUPPORTED",
  "reason": "No resistance method valid at Fn=0.46, Cp=0.53",
  "available_methods": [{"name": "holtrop", "gap": "Fn too high"}, ...],
  "recommendation": "CFD analysis or model test required"
}
```

**CURRENT STANCE:** System uses Continuous Parameter-Space Weighting with explicit gap detection and uncertainty disclosure.

**FORBIDDEN:**
- Categorical branching (e.g., `if regime == "planing"`)
- Method switching without disclosed weights
- Silent extrapolation beyond validity envelopes
- Use of terms "planing," "displacement," or "semi-displacement" in code or output

## 7. Multi-Body Doctrine (Parallel Axis Theorem)

Multi-hull vessels (Catamarans, Trimarans) are not "categories"; they are geometric configurations.

### 7.0 Global Coordinate System for Multi-Body Configurations

**Problem:** The Parallel Axis Theorem requires distances from individual hull centroids to the global origin. Without a defined origin, $d^2$ terms are ambiguous.

**Definition:** For multi-body configurations, the **Global Origin** is defined as:

$$O_{global} = (x_0, y_0, z_0)$$

where:
- $x_0$ = Aft Perpendicular (AP) of the **main hull** (or centroid of hull group if no designated main)
- $y_0$ = Centerline (CL) of the vessel (geometric center of all bodies)
- $z_0$ = Baseline (BL) of the lowest hull

**Hull Centroid Offsets:**

For body $k$ with local centroid $(x_k, y_k, z_k)$:

$$d_k = |y_k - y_0| \quad \text{(transverse offset for } BM_T \text{ calculation)}$$

**Multi-Body Transform:**

Each body $B_k$ is defined by:
```
Body_k = {
    geometry: SectionSet_k,
    offset: (Δx_k, Δy_k, Δz_k),  // Relative to global origin
    rotation: (φ_k, θ_k, ψ_k)   // Usually (0, 0, 0) for conventional hulls
}
```

### 7.0.1 Transverse Stability (Parallel Axis Theorem)

Transverse Metacentric Radius ($BM_T$) is computed using the **Parallel Axis Theorem**:

$$I_{total} = \sum_{k=1}^{n} (I_{local,k} + A_{wp,k} \times d_k^2)$$

where:
- $I_{local,k}$ = Transverse moment of inertia of body $k$ about its own centroid
- $A_{wp,k}$ = Waterplane area of body $k$
- $d_k$ = Transverse distance from body $k$ centroid to global centerline

This ensures that stability is a consequence of geometry, not a hard-coded "catamaran multiplier."

### 7.0.2 The Emergence Discontinuity

At large heel angles, the theory must account for hull emergence. When a hull leaves the water:
- The $A_{wp,k} \times d_k^2$ term for that hull approaches zero
- The Jacobian $\frac{\partial I_{total}}{\partial \phi}$ has a discontinuity
- The stack must handle this via the damping functions in Section 7.1

### 7.1 Numerical Discontinuity at Emergence ($A_{wp} \to 0$)

**Problem:** During iterative drafting, a multi-hull near the emergence threshold may "flicker" between emerged and submerged states. This causes:
- GZ curve discontinuities (Jacobian singular at $A_{wp} = 0$)
- Spiral oscillation (design never converges)
- Numerical instability in gradient-based optimization

**Formal Requirement:** To prevent "Spiral Jitter," implement a $C^2$ continuous weighting function for waterplane area near emergence.

**Solution:** Apply a damping coefficient when a hull is near emergence:

**Emergence Proximity Detection:**
```python
def detect_emergence_proximity(hull: MultiBody, heel_deg: float) -> EmergenceState:
    """Detect if any body is near emergence transition."""
    for body in hull.bodies:
        draft_at_heel = body.effective_draft(heel_deg)
        emergence_threshold = body.keel_depth * 0.05  # 5% of body depth

        if draft_at_heel < emergence_threshold:
            return EmergenceState(
                status="NEAR_EMERGENCE",
                body_id=body.id,
                draft_remaining_m=draft_at_heel,
                heel_at_emergence=estimate_emergence_heel(body)
            )

    return EmergenceState(status="SUBMERGED")
```

**Damping Coefficient Application:**

When within the emergence transition band (5% of body depth above/below emergence):

```
I_effective = I_local × ψ(r)

Where r = draft_remaining / emergence_threshold (normalized to [0, 1])
```

**Quintic Hermite Transition Function (C³ Continuous):**

The transition function $\psi(t)$ must be smooth enough for optimization:
- Value continuous (no jump in $I$)
- First derivative continuous (no kink in GZ curve)
- Second derivative continuous (no curvature discontinuity)
- Third derivative continuous (smooth for gradient-based optimization)

**Specific Form (Quintic Hermite Blend):**

$$\psi(t) = \begin{cases}
0 & t \leq 0 \text{ (fully emerged)} \\
6t^5 - 15t^4 + 10t^3 & 0 < t < 1 \text{ (transition band)} \\
1 & t \geq 1 \text{ (fully submerged)}
\end{cases}$$

**Properties of This Function:**
- $\psi(0) = 0$, $\psi(1) = 1$
- $\psi'(0) = \psi'(1) = 0$
- $\psi''(0) = \psi''(1) = 0$
- Monotonically increasing in $(0, 1)$

**Implementation:**

```python
def quintic_hermite(t: float) -> float:
    """
    C³-continuous transition function for emergence damping.

    Args:
        t: Normalized draft ratio [0, 1]
           t = 0: hull fully emerged
           t = 1: hull fully submerged

    Returns:
        ψ(t): Transition weight in [0, 1]
    """
    if t <= 0:
        return 0.0
    elif t >= 1:
        return 1.0
    else:
        # 6t⁵ - 15t⁴ + 10t³
        t3 = t * t * t
        return t3 * (10 + t * (-15 + 6 * t))


def quintic_hermite_derivative(t: float) -> float:
    """
    Derivative of transition function (for Jacobian).

    ψ'(t) = 30t⁴ - 60t³ + 30t²
          = 30t²(t - 1)²
    """
    if t <= 0 or t >= 1:
        return 0.0
    else:
        t2 = t * t
        return 30 * t2 * (1 - t) * (1 - t)
```

**Why C³ Matters for Optimization:**

| Continuity | Implication for Solver |
|------------|------------------------|
| C⁰ (value) | GZ curve has no jump |
| C¹ (derivative) | Gradient exists (Newton works) |
| C² (curvature) | Hessian exists (second-order methods work) |
| C³ (third) | No oscillation in adaptive step sizing |

**Comparison to Simpler Functions:**

| Function | Continuity | Issue |
|----------|------------|-------|
| Step function | C⁻¹ | Jacobian undefined |
| Linear ramp | C⁰ | Kink in GZ, gradient jumps |
| Sinusoidal | C∞ | Works, but overshoots at boundaries |
| Quintic Hermite | C³ | Optimal: smooth, monotonic, exact at boundaries |

### 7.1.1 Alternative: Sigmoid Dampening Function

For applications requiring explicit stiffness control, a sigmoid form may be used:

$$A_{wp,eff}(T) = A_{wp,full} \cdot \sigma\left(\frac{T - T_{emerg}}{\delta}\right)$$

where:
- $\sigma(x) = \frac{1}{1 + e^{-kx}}$ is the sigmoid function
- $k$ is the stiffness parameter (recommended: $k = 10$)
- $\delta$ is the transition width (recommended: $\delta = 0.05 \cdot T_{design}$)
- $T_{emerg}$ is the draft at which emergence begins

**Numerical Parameters:**

| Parameter | Symbol | Recommended Value | Rationale |
|-----------|--------|-------------------|-----------|
| Transition width | $\delta$ | $0.05 \cdot T_{design}$ | 5% of design draft |
| Sigmoid stiffness | $k$ | 10 | Ensures 99% transition within $\pm 2\delta$ |
| Emergence threshold | $T_{emerg}$ | $0.02 \cdot T_{design}$ | 2% of design draft |

**Jacobian Non-Singularity:** This ensures the Jacobian remains non-singular for gradient-based design suggestions, as $\frac{\partial A_{wp,eff}}{\partial T}$ is always finite.

## 8. Mutation Control and Numerical Noise Floor

The geometry kernel is locked against unintended modification. This section defines what constitutes a "mutation" versus numerical noise.

### 8.0 The Mutation Epsilon ($\epsilon_{mut}$)

**Definition:** A **Mutation Violation** is triggered if any geometric property $Q$ (Area, Volume, Inertia) changes by more than the numerical noise floor $\epsilon_{mut}$ without an explicit transform request.

**Constraint:**
$$\frac{|Q_{after} - Q_{before}|}{|Q_{before}|} > \epsilon_{mut} \implies \text{MUTATION\_VIOLATION}$$

**Threshold Values:**

| Resolution Level | $\epsilon_{mut}$ | Rationale |
|-----------------|------------------|-----------|
| L1 (Interactive) | $10^{-4}$ (0.01%) | Allows floating-point accumulation |
| L2 (Engineering) | $10^{-6}$ (0.0001%) | Tighter for validation |

**Floating-Point Allowance:** Coordinate rotation and transformation operations may accumulate floating-point errors. These are NOT mutations if bounded within $\epsilon_{fp} = 10^{-12}$ (machine epsilon scale).

### 8.1 Mutation Classification

A "mutation" is any operation that changes geometry between:
`Agent proposal → compiled canonical sections → downstream physics inputs`

Mutations are allowed **only if**:
- Recorded in `transform_report` with before/after hashes and numeric deltas
- Change exceeds $\epsilon_{mut}$ (otherwise it's numerical noise, not mutation)
- Classified as one of:
  - `REPRESENTATION`: e.g., resampling to N points
  - `NUMERICAL_STABILIZATION`: e.g., epsilon to prevent division by zero
  - `USER_APPROVED_EDIT`: explicit requested change

### 8.2 Default Policy

**If a geometry issue is detected, prefer REJECT WITH REASON over auto-repair.**

The system must not:
- Silently clamp values to "reasonable" ranges
- Auto-fair geometry without logging
- Dedupe or canonicalize in ways that change physics outputs by more than $\epsilon_{mut}$
- Apply any transform that an agent cannot observe

```python
    if lock["direction"] == direction:
        return True

    # Opposite direction requires human approval
    return state.has_pending_human_approval(param)
```

## 9. Validation Strategy for Infinitely Novel Forms

### 9.1 The Two Domains of Physics

MAGNET validates against physics primitives, not vessel types. This enables infinite novelty.

**Domain 1: Geometric Physics (Unbounded Novelty)**

These quantities are pure geometry. They are equally valid for any form—conventional or novel.

| Quantity | Calculation Basis | Novelty Impact |
|----------|-------------------|----------------|
| Displaced volume | Integration over geometry | None—math is math |
| Waterplane area | Integration over geometry | None |
| Centers (LCB, VCB, LCF) | First moment of geometry | None |
| Moments of inertia (It, Il) | Second moment of geometry | None |
| Metacentric radius (BM) | I / V | None |
| GZ curve (large angle) | Volume integration at each heel | None |

**Domain 2: Empirical Physics (Bounded Validity)**

These quantities depend on regression against existing data. They have validity envelopes.

| Quantity | Calculation Basis | Novelty Impact |
|----------|-------------------|----------------|
| Frictional resistance | ITTC correlation | Low—flat plate assumption universal |
| Wave resistance (Holtrop) | Regression on merchant ships | High—Cp, L/B, Fn bounds |
| Planing lift/drag (Savitsky) | Regression on prismatic planing | High—deadrise, Fn bounds |

### 9.2 The Novelty Response Matrix

| Quantity | Conventional Form | Moderately Novel | Radically Novel |
|----------|-------------------|------------------|-----------------|
| Volume | ±0.5% | ±0.5% | ±0.5% |
| LCB | ±0.5% L | ±0.5% L | ±0.5% L |
| BM | ±2% | ±2% | ±2% |
| GM | ±5% + σ_VCG | ±5% + σ_VCG | ±5% + σ_VCG |
| GZ curve | Valid | Valid | Valid |
| Resistance | ±10-15% | ±20-30% | **UNSUPPORTED** |
| Power | ±15-20% | ±25-35% | **UNSUPPORTED** |

**Key insight:** Hydrostatics and stability are geometry-derived—they don't care about novelty. Resistance is regression-derived—it cares deeply about novelty.

### 9.3 Uncertainty Scaling Rules

**For Geometric Quantities:**
```
σ_geometric ≈ 0.5%
# Independent of novelty—a sphere and a bizarre hull have equal uncertainty
```

**For Stability Quantities:**
```
σ_GM = √(σ_BM² + σ_KG²)
# BM uncertainty is geometric (~2%)
# KG uncertainty is from weight estimation (~10-20%)
# GM uncertainty dominated by weight, not geometry
```

**For Resistance:**
```
IF form inside method envelope:    σ = ±10-15%
IF form at envelope edge:          σ = ±20-25% + EXTRAPOLATED flag
IF form outside all envelopes:     UNSUPPORTED—recommend CFD/model test
```

**Level 1: Mathematical Verification (Proves the Integrator)**

Test against shapes with closed-form solutions:

| Test Shape | Closed-Form Property | Purpose |

### 12.2 Convergence Rate Reporting

**Problem:** Users need to understand whether the solver is making progress, oscillating, or stuck. Raw iteration counts are insufficient.

**Solution:** Report convergence rate and behavior classification with each result.

**Convergence Rate Estimation:**

For residual sequence $\{r_1, r_2, \ldots, r_n\}$, estimate the convergence rate:

$$q = \frac{\log(r_n / r_{n-1})}{\log(r_{n-1} / r_{n-2})}$$

| Estimated $q$ | Convergence Type | Meaning |
|---------------|------------------|---------|
| $q \approx 1$ | Linear | Each iteration reduces error by constant factor |
| $q \approx 2$ | Quadratic | Newton-like, fast near solution |
| $q > 2$ | Superlinear | Excellent, approaching solution rapidly |
| $q < 1$ or negative | Sublinear/Stalled | Progress slow or oscillating |

**Stall Detection:**

```python
def check_stall(residual_history: List[float], window: int = 3) -> StallStatus:
    """
    Detect if solver is stalled or oscillating.

    Stall: Residual not decreasing over window iterations
    Oscillation: Residual alternating up/down
    """
    if len(residual_history) < window:
        return StallStatus(stalled=False, oscillating=False)

    recent = residual_history[-window:]

    # Check monotonic decrease
    decreasing = all(recent[i] > recent[i+1] for i in range(window-1))

    # Check alternating pattern (oscillation)
    diffs = [recent[i+1] - recent[i] for i in range(window-1)]
    alternating = all(diffs[i] * diffs[i+1] < 0 for i in range(len(diffs)-1))

    # Check stall (no progress)
    stalled = (max(recent) - min(recent)) / max(recent) < 0.01

    return StallStatus(
        stalled=stalled,
        oscillating=alternating and not decreasing,
        rate=estimate_convergence_rate(recent) if decreasing else None
    )
```

## 13. Architectural Philosophy

### 13.1 The Canonical Physical Object (The Single Truth)

To avoid divergence between solvers, MAGNET/CORTEX defines a single authority for physical truth:

1. **The Primary Truth: The Section Set.**
   The discretized longitudinal sections (Y-Z curves) are the canonical representation for all hydrostatics, volume integration, and stability calculations.
2. **The Derived Truth: The Mesh.**
   The triangle mesh (tessellated surface) is a secondary representation used for visualization, WebGL rendering, and export. It is *derived* from the sections and must never be used as the authority for volume or weight balance.
3. **The Synchronization Scar:**
   Discrepancies between Section-derived volume and Mesh-derived volume are expected (typically <0.5%). The system acknowledges this "bleed" and always defers to the Section Set for the legal load line.

### 15.6 Numerical Scars & Sampling Drift

Reality is messy, and discretization introduces artifacts. The system explicitly acknowledges these "scars":

1.  **Spline Drift:** Resampling raw user points to a normalized `target_n=32` spline introduces sub-millimeter drift. This is the "cost of fairing."
2.  **Section Aliasing:** A hull with 20 sections cannot perfectly represent a complex bulbous bow. The theory accepts a volumetric error of up to 1% for performance.
3.  **The B-Spline Compromise:** High-curvature areas (chines) may "ring" slightly when using cubic interpolation. We prioritize fairing (smoothness) over 100% point-accuracy.

## 16. Hydrostatics Theory

### 16.1 Fundamental Principle

> **Archimedes:** A floating body displaces a volume of water equal to its weight.

```
Δ = ρ × ∇

Where:
  Δ = Displacement (mass) [tonnes]
  ρ = Water density [t/m³] (1.025 for seawater)
  ∇ = Submerged volume [m³]
```

### 16.2 Volume Integration

Submerged volume is computed by numerical integration:

**Method 1: Trapezoidal (Station Integration)**
```
∇ = ∫₀ᴸ A(x) dx ≈ Σᵢ (Aᵢ + Aᵢ₊₁)/2 × Δx

Where:
  A(x) = Submerged section area at station x
  L = Length on waterline
```

**Method 2: Mesh Integration (Divergence Theorem)**
```
∇ = (1/3) × Σᵢ (vᵢ · nᵢ) × Aᵢ

Where:
  vᵢ = Centroid of triangle i
  nᵢ = Normal vector of triangle i
  Aᵢ = Area of triangle i
```

### 16.3 Section Area Calculation (Green's Theorem Formulation)

For a single section at draft T, we use Green's Theorem to convert 2D area integrals to efficient 1D line integrals.

**Green's Theorem for Polygon Area:**

For a closed polygon with vertices $(y_1, z_1), (y_2, z_2), \ldots, (y_n, z_n)$:

$$A = \frac{1}{2} \sum_{i=1}^{n} (y_i z_{i+1} - y_{i+1} z_i)$$

where indices wrap: $(y_{n+1}, z_{n+1}) = (y_1, z_1)$.

**Why This Formulation:**
- Converts 2D area integral to 1D line integral (efficient)
- Works for arbitrary polygons (supports novel forms)
- Exact for polygonal sections (no approximation error from the method itself)
- Handles concave sections correctly (signed area)

**Implementation:**

```python
def section_area_greens(points: List[Point2D]) -> float:
    """
    Compute section area using Green's theorem.

    Points must be ordered counterclockwise for positive area.
    For hull sections: keel → chine → sheer → waterline → keel
    """
    n = len(points)
    area = 0.0

    for i in range(n):
        j = (i + 1) % n  # Wrap around
        y_i, z_i = points[i]
        y_j, z_j = points[j]
        area += (y_i * z_j - y_j * z_i)

    return abs(area) / 2.0
```

**First Moment (for Center of Area):**

$$\bar{y} = \frac{1}{6A} \sum_{i=1}^{n} (y_i + y_{i+1})(y_i z_{i+1} - y_{i+1} z_i)$$

$$\bar{z} = \frac{1}{6A} \sum_{i=1}^{n} (z_i + z_{i+1})(y_i z_{i+1} - y_{i+1} z_i)$$

**Second Moment (for Moment of Inertia):**

$$I_y = \frac{1}{12} \sum_{i=1}^{n} (z_i^2 + z_i z_{i+1} + z_{i+1}^2)(y_i z_{i+1} - y_{i+1} z_i)$$

$$I_z = \frac{1}{12} \sum_{i=1}^{n} (y_i^2 + y_i y_{i+1} + y_{i+1}^2)(y_i z_{i+1} - y_{i+1} z_i)$$

**Validation Against Closed Forms:**

| Test Shape | Vertices | Closed-Form Area | Purpose |
|------------|----------|------------------|---------|
| Rectangle (4 vertices) | $[(0,0), (B,0), (B,T), (0,T)]$ | $A = B \times T$ | Verify basic polygon |
| Triangle (3 vertices) | $[(0,0), (B,0), (B/2,T)]$ | $A = \frac{1}{2} B \times T$ | Verify signed area |
| Trapezoid | $[(0,0), (B_1,0), (B_2,T), (0,T)]$ | $A = \frac{1}{2}(B_1 + B_2) \times T$ | Verify non-rectangular |
| Circle (N vertices) | $N \to \infty$ | $A \to \pi r^2$ | Verify convergence |

**Acceptance Criterion:** Agreement to < 0.01% proves integrator correct for ANY shape.

### 16.3.1 Analytical Sensitivity Derivation

Since area is a polynomial in vertex coordinates (from Green's theorem), sensitivities $\frac{\partial A}{\partial y_i}$ and $\frac{\partial A}{\partial z_i}$ are also polynomial and can be computed analytically.

**Sensitivity of Area to Vertex Position:**

From $A = \frac{1}{2} \sum_{i=1}^{n} (y_i z_{i+1} - y_{i+1} z_i)$:

$$\frac{\partial A}{\partial y_i} = \frac{1}{2}(z_{i+1} - z_{i-1})$$

$$\frac{\partial A}{\partial z_i} = \frac{1}{2}(y_{i-1} - y_{i+1})$$

**Sensitivity of First Moment:**

$$\frac{\partial (A \cdot \bar{y})}{\partial y_i} = \frac{1}{6}\left[(2y_i + y_{i+1})(z_{i+1} - z_{i-1}) + (y_{i-1} + 2y_i)(z_i - z_{i-1})\right]$$

**Sensitivity of Second Moment (Transverse Inertia):**

For waterplane inertia $I_t = \int y^2 dA$:

$$\frac{\partial I_t}{\partial B} = \frac{3 I_t}{B}$$

(Wall-sided approximation: $I_t \propto B^3$)

**Why Analytical Sensitivities Matter:**

| Method | Accuracy | Cost | Noise |
|--------|----------|------|-------|
| Finite Difference | ±0.1-1% | 2N evaluations | High at small ε |
| Analytical | Exact | 1 evaluation | None |

**Integration with Design Jacobian:**

The analytical sensitivities feed directly into the suggested-fix Jacobian:

```python
def compute_geometric_jacobian(hull: HullGeometry) -> np.ndarray:
    """
    Compute Jacobian of geometric quantities analytically.

    Returns J where J[i,j] = ∂(quantity_i) / ∂(parameter_j)

    Quantities: [V, A_wp, I_t, LCB, KB]
    Parameters: [y_vertices, z_vertices, station_spacing]
    """
    J = np.zeros((5, len(hull.all_vertices) * 2))

    for section_idx, section in enumerate(hull.sections):
        # Compute ∂A/∂y, ∂A/∂z for each vertex
        dA_dy, dA_dz = analytical_area_sensitivities(section.points)

        # Chain rule: ∂V/∂y = Δx × ∂A/∂y
        dx = hull.station_spacing[section_idx]
        J[0, vertex_indices] = dx * dA_dy  # Volume sensitivity

        # Continue for other quantities...

    return J
```

**Benefit:** Eliminates finite-difference noise in geometric sensitivities, enabling reliable suggested fixes.

### 16.5 Centers of Buoyancy

**Longitudinal Center of Buoyancy (LCB):**
```
LCB = ∫ x × A(x) dx / ∇

# Discrete form:
LCB = Σᵢ xᵢ × Aᵢ × Δx / ∇
```

**Vertical Center of Buoyancy (VCB or KB):**
```
KB = ∫∫∫ z dV / ∇

# Approximation for conventional hulls:
KB ≈ T × (0.9 - 0.36 × Cm)  # Morrish formula
KB ≈ T × (5/6 - Cb/(3×Cw))  # Alternative
```

### 16.6 Waterplane Properties

**Waterplane Area (Aw):**
```
Aw = ∫₀ᴸ B(x) dx

Where B(x) = beam at waterline at station x
```

**Longitudinal Center of Flotation (LCF):**
```
LCF = ∫ x × B(x) dx / Aw
```

**Transverse Moment of Inertia (Iₜ):**
```
Iₜ = ∫₀ᴸ (B(x)³/12) dx  # For rectangular approximation

# Or exact integration:
Iₜ = ∫₀ᴸ ∫₋ᴮ⁄²ᴮ⁄² y² dy dx
```

**Longitudinal Moment of Inertia (Iₗ):**
```
Iₗ = ∫₀ᴸ x² × B(x) dx - Aw × LCF²
```

### 16.7 Metacentric Height

```
            │
            │  M (Metacenter)
            │
            │  ← GM
            │
            G (Center of Gravity)
            │
            │  ← BG
            │
            B (Center of Buoyancy)
            │
            │  ← KB
            │
    ════════╧════════  Baseline
```

**Transverse Metacentric Radius (BMₜ):**

```
BMₜ = Iₜ / ∇
```

**Transverse Metacentric Height (GMₜ):**

```
Where:
```

- GM = 0: Neutral (indifferent equilibrium)
- GM < 0: Unstable (capsizes)

## 17. Stability Theory

### 17.1 Initial Stability (The Small-Angle Approximation)

For small heel angles (φ < 7°), the system uses the metacentric height:

```
GZ ≈ GM × sin(φ)
```

**The 7-Degree Boundary:** Engineers distrust small-angle formulas for beamier vessels. The system enforces a switch:
- **Upright (0-7°):** Wall-sided approximation (fast).
- **Heeled (> 7°):** Full cross-curve integration (accurate).

### 17.2 Trim Equilibrium (Critical for Credible Stability)

**Problem:** Real vessels float at equilibrium trim, not at imposed trim = 0. Without solving trim equilibrium, GZ curves are systematically wrong.

**Physics:** At equilibrium, the vessel satisfies:
1. **Vertical force balance:** $\rho g \nabla = W$ (displacement = weight)
2. **Longitudinal moment balance:** $LCB = LCG$ (no trimming moment)

**Trim Equation:**

$$\theta_{trim} = \frac{(LCG - LCB) \cdot W}{\rho g \cdot IL / L_{wl}}$$

where $IL$ is the longitudinal moment of inertia of the waterplane.

**Coupled Draft-Trim Solver:**

```python
def solve_equilibrium(hull: HullGeometry, weight: float, lcg: float, vcg: float,
                      tolerance: float = 1e-4) -> EquilibriumState:
    """
    Solve for equilibrium draft AND trim simultaneously.

    Newton-Raphson iteration on residual vector:
    R = [ρg∇ - W, LCB - LCG]

    Jacobian:
    J = [[∂(ρg∇)/∂T, ∂(ρg∇)/∂θ],
         [∂LCB/∂T,   ∂LCB/∂θ  ]]
    """
    # Initial guess
    T = estimate_draft(hull, weight)
    theta = 0.0

    for iteration in range(MAX_ITERATIONS):
        # Compute hydrostatics at current (T, θ)
        hydro = compute_hydrostatics_at_trim(hull, T, theta)

        # Residual vector
        R = np.array([
            RHO_SW * G * hydro.volume - weight,
            hydro.lcb - lcg
        ])

        if np.linalg.norm(R, ord=np.inf) < tolerance:
            return EquilibriumState(
                draft=T,
                trim_deg=np.degrees(theta),
                converged=True,
                iterations=iteration
            )

        # Jacobian (computed analytically or by finite differences)
        J = compute_equilibrium_jacobian(hull, T, theta, hydro)

        # Newton update
        delta = np.linalg.solve(J, -R)
        T += delta[0]
        theta += delta[1]

    return EquilibriumState(converged=False)
```

**Convergence Residuals (Unified):**

$$Res_{\Delta} = \frac{| \rho g \nabla - W |}{W}$$

$$Res_{\tau} = \frac{| LCB - LCG |}{L_{wl}}$$

**Stopping Criterion:** $\| \mathbf{Res} \|_{\infty} < \epsilon_{mode}$

| Mode | $\epsilon$ | Typical Iterations |
|------|------------|-------------------|
| Interactive | 0.02 | 3-5 |
| Engineering | 0.002 | 5-10 |

### 17.2.1 Free-to-Trim GZ Computation

**Critical Requirement:** For credible GZ curves, trim must be solved at EACH heel angle.

```python
def compute_GZ_curve_free_to_trim(hull: HullGeometry, weight: float,
                                   lcg: float, vcg: float,
                                   angles: List[float]) -> GZCurve:
    """
    Compute GZ at each heel angle with trim equilibrium.

    At each heel:
    1. Rotate geometry by φ
    2. Solve for equilibrium draft AND trim
    3. Compute GZ at equilibrium condition
    """
    GZ_curve = []

    for phi in angles:
        # Rotate section set by heel angle
        rotated_hull = rotate_geometry(hull, phi)

        # Solve equilibrium at this heel (MUST include trim)
        equilibrium = solve_equilibrium(rotated_hull, weight, lcg, vcg)

        # Compute center of buoyancy at equilibrium
        hydro = compute_hydrostatics_at_trim(
            rotated_hull,
            equilibrium.draft,
            equilibrium.trim_rad
        )

        # GZ = horizontal distance from G to vertical through B'
        # In rotated coordinates:
        G_rotated = rotate_point((0, vcg), phi)
        B_rotated = (hydro.tcb, hydro.vcb)  # Transverse and vertical CB

        # GZ is the horizontal separation
        GZ = B_rotated[0] - G_rotated[0]

        GZ_curve.append({
            "heel_deg": phi,
            "GZ_m": GZ,
            "trim_deg": equilibrium.trim_deg,  # MUST REPORT THIS
            "draft_m": equilibrium.draft,
            "equilibrium_converged": equilibrium.converged
        })

    return GZCurve(points=GZ_curve)
```

**Output Contract:**

Every GZ point must include trim at which it was computed:

```json
{
  "heel_deg": 30.0,
  "GZ_m": 0.85,
  "trim_deg": 1.2,
  "draft_m": 2.15,

}
```

**Why This Matters:**

| Approach | Physical Validity | Error Magnitude |

| Fixed trim (θ = 0) | Incorrect | 5-20% GZ error |

### 17.3 Large Angle Stability (Mesh/Section Integration)

For larger angles, the "wall-sided" formula is discarded. The system performs exact integration with free-to-trim equilibrium:

**Exact Method (Cross-Curve Integration):**
```
At each heel angle φ:
1. Rotate canonical section set by φ
2. Find new waterline for equilibrium (∇ = constant, M_trim = 0)
3. Calculate new center of buoyancy B'
4. GZ = horizontal distance from G to vertical through B'
5. Record equilibrium trim for audit trail
```

**The Non-Linearity Scar:** GZ curves for catamarans or hard-chine hulls will show abrupt slope changes when a hull emerges or a chine immerses. The system reports these as physical facts, not errors.

### 18.2 Hull Weight Estimation

```python
def estimate_hull_weight_aluminum(L, B, D, Cb):
```

**Geometry-Derived Formula (Preferred):**
```python
def estimate_hull_weight_from_geometry(hull: HullGeometry,
                                        material: str = "aluminum"):
    """
    Compute weight from actual wetted surface area.

    W_hull = ρ_material × Σᵢ (Aᵢ × tᵢ)

    Where:
      Aᵢ = Area of panel i
      tᵢ = Thickness of panel i (from scantling rules)

    densities = {"steel": 7850, "aluminum": 2700, "frp": 1800}
```

### 18.7 Center of Gravity

**Vertical Center of Gravity (VCG/KG):**
```
KG = Σᵢ (Wᵢ × KGᵢ) / Σᵢ Wᵢ

Typical component heights:
  - Hull: 0.55 × D (depth)
  - Machinery: 0.30 × D
  - Superstructure: D + 0.5 × Hs
  - Fuel (low): 0.3 × D
  - Payload (deck): D + 1.0
```

**Longitudinal Center of Gravity (LCG):**
```
LCG = Σᵢ (Wᵢ × LCGᵢ) / Σᵢ Wᵢ

# Must balance with LCB for zero trim
Trim = (LCG - LCB) × Δ / (ρ × Iₗ / L)
```

## 19. Resistance & Propulsion Theory

### 19.1 Total Resistance Decomposition

```
Rₜ = Rᶠ + Rᵣ + Rₐₚₚ + Rₐᵢᵣ

Where:
  Rᶠ = Frictional resistance (viscous)
  Rᵣ = Residuary resistance (wave-making)
  Rₐₚₚ = Appendage resistance
  Rₐᵢᵣ = Air resistance
```

### 19.2 Froude Number Regimes

```
Fn = V / √(g × L)

Where:
  V = Speed [m/s]
  g = Gravity [9.81 m/s²]
  L = Waterline length [m]
```

| Fn Range | Regime | Dominant Resistance | Method |
|----------|--------|---------------------|--------|
| 0 - 0.25 | Displacement | Frictional | Holtrop-Mennen |
| 0.25 - 0.5 | Semi-displacement | Wave + Friction | Holtrop + empirical |
| 0.5 - 1.0 | Semi-planing | Wave + Dynamic lift | Savitsky transitional |
| > 1.0 | Planing | Dynamic lift | Savitsky |

### 19.3 Frictional Resistance (ITTC 1957)

```
Rᶠ = ½ × ρ × V² × S × Cᶠ

Cᶠ = 0.075 / (log₁₀(Rn) - 2)²

Where:
  S = Wetted surface area [m²]
  Rn = Reynolds number = V × L / ν
  ν = Kinematic viscosity [1.19×10⁻⁶ m²/s for seawater at 15°C]
```

### 19.4 Holtrop-Mennen Method (Displacement Hulls)

```python
def holtrop_mennen(L, B, T, Cb, Cp, V, S):
    """
    Statistical regression for displacement vessels.
    Fn < 0.45
    """
    Fn = V / sqrt(9.81 * L)

    # Form factor (1+k1)
    k1 = 0.93 + 0.487 * (L/B)**(-1.68) * ...

    # Wave resistance coefficient
    c1 = 2223105 * (Cp)**3.7861 * ...
    Cw = c1 * exp(-1.89 * sqrt(m1)) * ...

    # Total resistance
    Rt = 0.5 * rho * V**2 * S * (Cf * (1+k1) + Cw)

    return Rt
```

### 19.5 Savitsky Method (Planing Hulls)

```python
def savitsky_planing(L, B, deadrise_deg, W, V):
    """
    Prismatic planing hull resistance.
    Fn > 0.5, deadrise > 10°
    """
    β = radians(deadrise_deg)
    Cv = V / sqrt(9.81 * B)  # Speed coefficient

    # Lift coefficient
    Cl0 = τ**1.1 * (0.012 * sqrt(λ) + 0.0055 * λ**2.5 / Cv**2)
    Clβ = Cl0 - 0.0065 * β * Cl0**0.6

    # Drag components
    Df = 0.5 * rho * V**2 * λ * B**2 * Cf  # Friction
    Di = W * tan(τ)  # Induced drag

    Rt = Df + Di

    return Rt, τ  # Also return trim angle
```

### 19.6 Resistance Selection Logic (Doctrine Compliant)

**DOCTRINE REALITY CHECK:** No universal, continuous resistance model exists for all (geometry, speed) pairs. The system adopts **Option B (Regime-Aware Blending)** with explicit gap detection.

```python
def compute_resistance(hull, V) -> ResistanceResult:
    """
    Compute resistance with continuous blending and gap detection.

    Doctrine Compliance:
    - Methods blended via smooth sigmoid weight functions
    - Gaps explicitly detected and reported as UNSUPPORTED
    - Every output carries validity envelope and uncertainty
    - Selection weights always disclosed for audit
    """
    Fn = V / sqrt(9.81 * hull.Lwl)
    deadrise = hull.get_midship_deadrise()
    Cp = hull.compute_prismatic_coefficient()

    # --- Method validity envelopes ---
    holtrop_valid = (0.15 <= Fn <= 0.45) and (0.55 <= Cp <= 0.85)
    savitsky_valid = (Fn >= 0.5) and (deadrise >= 10)

    # --- Handle gaps explicitly ---
    if not holtrop_valid and not savitsky_valid:
        return ResistanceResult(
            status="UNSUPPORTED",
            reason=f"No method valid at Fn={Fn:.3f}, Cp={Cp:.3f}, deadrise={deadrise:.1f}°",
            available_methods=[
                {"name": "holtrop", "gap": "Fn or Cp outside envelope"},
                {"name": "savitsky", "gap": "Fn too low or deadrise too shallow"}
            ]
        )

    # --- Compute method outputs ---
    R_hm = holtrop_mennen(hull, V) if holtrop_valid else None
    R_sav = savitsky_planing(hull, V) if savitsky_valid else None

    # --- Continuous weight functions (sigmoid blending) ---
    w_holtrop = 1.0 / (1.0 + exp(20 * (Fn - 0.45))) if holtrop_valid else 0.0
    deadrise_factor = 1.0 / (1.0 + exp(-2 * (deadrise - 10)))
    w_savitsky = (1.0 - w_holtrop) * deadrise_factor if savitsky_valid else 0.0

    # Normalize weights
    w_total = w_holtrop + w_savitsky + 1e-10
    w_holtrop /= w_total
    w_savitsky /= w_total

    # --- Determine validity status per method ---
    validity = {}
    if holtrop_valid:
        validity["holtrop"] = "NOMINAL" if (0.20 <= Fn <= 0.40) else "EXTRAPOLATED"
    if savitsky_valid:
        validity["savitsky"] = "NOMINAL" if (Fn >= 0.6 and deadrise >= 15) else "EXTRAPOLATED"

    # --- Blended result ---
    R_total = 0
    if R_hm is not None:
        R_total += w_holtrop * R_hm
    if R_sav is not None:
        R_total += w_savitsky * R_sav

    # --- Uncertainty increases in transition zones and extrapolation ---
    transition_uncertainty = 4 * w_holtrop * w_savitsky
    extrapolation_penalty = 0.10 if any(v == "EXTRAPOLATED" for v in validity.values()) else 0
    base_uncertainty = 0.10
    uncertainty = base_uncertainty + 0.15 * transition_uncertainty + extrapolation_penalty

    return ResistanceResult(
        status="OK",
        Rt=R_total,
        selection_weights={"holtrop": w_holtrop, "savitsky": w_savitsky},
        validity=validity,
        validity_envelope=f"Fn={Fn:.3f}, Cp={Cp:.3f}, deadrise={deadrise:.1f}°",
        uncertainty_level="HIGH" if uncertainty > 0.20 else "MED" if uncertainty > 0.12 else "LOW",
        uncertainty_pct=uncertainty
    )
```

**Key Compliance Features:**
- Gap detection returns `UNSUPPORTED` with reason (not silent failure)
- Methods only contribute when within validity envelope
- Extrapolation explicitly flagged (not silently accepted)
- Selection weights always emitted for audit
- Uncertainty quantified and disclosed

### 19.6.1 Gaussian Weighting (Multi-Method Generalization)

**Why Gaussian is Better Than Sigmoid:**

The sigmoid blending in Section 19.6 works for two methods but doesn't generalize well. Gaussian weighting naturally handles:
- Multiple methods (not just two)
- Methods with different validity radii
- Distance in multiple dimensions (Cp, L/B, Fn simultaneously)

**Mathematical Formulation:**

Each method $m$ has a center $\mathbf{c}_m$ and validity radius $\sigma_m$ in parameter space:

$$w_m = \exp \left( -\frac{\| \mathbf{p} - \mathbf{c}_m \|^2}{2 \sigma_m^2} \right)$$

where $\mathbf{p} = (Fn, Cp, L/B, \text{deadrise})$ is the current operating point.

**Method Centers and Radii:**

| Method | Center $\mathbf{c}_m$ | Radius $\sigma_m$ |
|--------|----------------------|-------------------|
| Holtrop-Mennen | $(Fn=0.30, Cp=0.70, L/B=6.0)$ | 0.15 |
| Savitsky | $(Fn=0.80, Cp=0.55, deadrise=20°)$ | 0.20 |
| NPL Series | $(Fn=0.50, Cp=0.60, L/B=5.0)$ | 0.12 |

**Implementation:**

```python
@dataclass
class ResistanceMethod:
    name: str
    center: np.ndarray      # Center in parameter space
    sigma: float            # Validity radius
    base_uncertainty: float # Baseline uncertainty when at center
    compute: Callable       # Function to compute resistance

RESISTANCE_METHODS = [
    ResistanceMethod("holtrop", np.array([0.30, 0.70, 6.0]), 0.15, 0.10, holtrop_mennen),
    ResistanceMethod("savitsky", np.array([0.80, 0.55, 20.0]), 0.20, 0.12, savitsky_planing),
    # Future methods can be added here
]

def compute_resistance_gaussian(hull, V, methods=RESISTANCE_METHODS) -> ResistanceResult:
    """
    Compute resistance with Gaussian weighting and gap detection.
    """
    # Current operating point
    p = np.array([
        V / sqrt(9.81 * hull.Lwl),              # Fn
        hull.compute_prismatic_coefficient(),    # Cp
        hull.L / hull.B                          # L/B or deadrise depending on method
    ])

    weights = []
    results = []
    distances = []

    for method in methods:
        # Distance to method center (normalized by sigma)
        d = np.linalg.norm((p - method.center) / method.sigma)
        distances.append(d)

        # Gaussian weight
        w = np.exp(-0.5 * d**2)
        weights.append(w)

        # Compute if weight is significant
        if w > 0.01:
            results.append(method.compute(hull, V))
        else:
            results.append(None)

    total_weight = sum(weights)

    # === GAP DETECTION ===
    WEIGHT_THRESHOLD = 0.1  # Below this, no method is confident

    if total_weight < WEIGHT_THRESHOLD:
        return ResistanceResult(
            status="UNSUPPORTED",
            reason="Novel form outside all method validity regions",
            weights={m.name: w for m, w in zip(methods, weights)},
            distances={m.name: d for m, d in zip(methods, distances)},
            distance_to_nearest=min(distances),
            recommendation="Consider CFD or model test for this geometry-speed combination"
        )

    # === UNCERTAINTY SCALING ===
    # Uncertainty increases as total weight decreases (less confidence)
    FULL_CONFIDENCE_WEIGHT = 0.8
    confidence_factor = min(1.0, total_weight / FULL_CONFIDENCE_WEIGHT)

    # Weighted average of base uncertainties
    weighted_uncertainty = sum(
        w * m.base_uncertainty for w, m in zip(weights, methods) if w > 0.01
    ) / (sum(w for w in weights if w > 0.01) + 1e-10)

    # Scale by confidence factor
    scaled_uncertainty = weighted_uncertainty / confidence_factor

    # === BLENDED RESULT ===
    R_total = sum(
        w * r for w, r in zip(weights, results) if r is not None
    ) / total_weight

    # Normalize weights for output
    normalized_weights = {m.name: w / total_weight for m, w in zip(methods, weights)}

    return ResistanceResult(
        status="OK",
        Rt=R_total,
        selection_weights=normalized_weights,
        distances={m.name: d for m, d in zip(methods, distances)},
        confidence_factor=confidence_factor,
        uncertainty_pct=scaled_uncertainty,
        uncertainty_level=classify_uncertainty(scaled_uncertainty)
    )


def classify_uncertainty(u: float) -> str:
    if u < 0.12:
        return "LOW"
    elif u < 0.20:
        return "MEDIUM"
    elif u < 0.30:
        return "HIGH"
    else:
        return "EXTREME"
```

**Uncertainty Scaling Rules:**

| Condition | Total Weight | Confidence | Uncertainty |
|-----------|--------------|------------|-------------|
| Inside one method's center | ~1.0 | 1.0 | Baseline (±10%) |
| Between methods | 0.5-0.8 | 0.6-1.0 | Increased (±15-20%) |
| At edges of all methods | 0.1-0.3 | 0.1-0.4 | High (±25-35%) |
| Outside all methods | < 0.1 | — | UNSUPPORTED |

**Why the Weight Threshold Matters:**

If all weights are near zero:
$$R_{total} = \frac{\sum w_m R_m}{\sum w_m} = \frac{\approx 0}{\approx 0} \quad \text{(undefined)}$$

The threshold prevents division by zero AND honestly reports when no method applies.

### 20.5 Sensitivity Derivatives for Upstream Feedback

**Problem:** The North Star requires the system to "Suggest Fixes" (e.g., "Increase beam by 0.3m to achieve GM > 0.5m"). To do this deterministically, the kernel must expose more than just results; it must expose **gradients**.

**Requirement:** Every physics grade (GM, Resistance, Freeboard) must return a **Sensitivity Vector** with respect to geometry primitives.

**Mathematical Basis:**

For a physics quantity $Q$ (e.g., GM, resistance, freeboard), compute sensitivities:

$$\frac{\partial Q}{\partial p_i}$$

Where $p_i$ are the geometry primitives: beam (B), length (L), draft (T), depth (D), body spacing, section shape parameters.

**Sensitivity Computation Methods:**

| Method | Accuracy | Cost | Use Case |
|--------|----------|------|----------|
| Finite Difference | ±1% | 2N evaluations | Default for all quantities |
| Adjoint | Exact | 1 evaluation + adjoint solve | Future: continuous optimization |
| Analytical | Exact | Closed-form | Simple quantities (BM, Aw) |

**Finite Difference Implementation:**

```python
def compute_sensitivity_vector(hull: HullGeometry,
                                quantity: str,
                                epsilon: float = 0.01) -> SensitivityVector:
    """
    Compute ∂Q/∂p for each geometry parameter.

    Returns sensitivity vector enabling fix suggestions:
    "Increase beam by ΔB to achieve target GM"
    """
    base_value = compute_quantity(hull, quantity)
    sensitivities = {}

    # Beam sensitivity
    hull_perturbed = hull.with_beam(hull.B * (1 + epsilon))
    perturbed_value = compute_quantity(hull_perturbed, quantity)
    sensitivities["beam"] = (perturbed_value - base_value) / (hull.B * epsilon)

    # Length sensitivity
    hull_perturbed = hull.with_length(hull.L * (1 + epsilon))
    perturbed_value = compute_quantity(hull_perturbed, quantity)
    sensitivities["length"] = (perturbed_value - base_value) / (hull.L * epsilon)

    # Draft sensitivity
    hull_perturbed = hull.with_draft(hull.T * (1 + epsilon))
    perturbed_value = compute_quantity(hull_perturbed, quantity)
    sensitivities["draft"] = (perturbed_value - base_value) / (hull.T * epsilon)

    # Depth sensitivity (affects freeboard, VCG)
    hull_perturbed = hull.with_depth(hull.D * (1 + epsilon))
    perturbed_value = compute_quantity(hull_perturbed, quantity)
    sensitivities["depth"] = (perturbed_value - base_value) / (hull.D * epsilon)

    return SensitivityVector(
        quantity=quantity,
        base_value=base_value,
        sensitivities=sensitivities,
        epsilon_used=epsilon
    )
```

**Analytical Sensitivities (Where Available):**

| Quantity | Sensitivity Formula | Notes |
|----------|---------------------|-------|
| $BM_T$ | $\frac{\partial BM_T}{\partial B} = \frac{3 I_T}{∇ B} = \frac{3 BM_T}{B}$ | Wall-sided approximation |
| $GM$ | $\frac{\partial GM}{\partial B} = \frac{\partial BM_T}{\partial B}$ | Assuming KB, KG constant |
| $A_w$ | $\frac{\partial A_w}{\partial B} = \frac{A_w}{B}$ | Linear scaling |
| Freeboard | $\frac{\partial F}{\partial T} = -1$ | Exact |

**Fix Suggestion Generation:**

```python
def generate_fix_suggestion(grade_result: GradeResult,
                            sensitivity: SensitivityVector) -> FixSuggestion:
    """
    Generate actionable fix suggestion from sensitivity analysis.

    Example output:
    "💡 Suggested Fix: Increase beam by 0.28m to achieve GM = 0.50m
     (Current: GM = 0.38m, ∂GM/∂B = 0.43 m/m)"
    """
    if grade_result.status != "VIOLATION":
        return None

    target = grade_result.threshold
    current = grade_result.value
    gap = target - current

    # Find most effective parameter (highest |sensitivity|)
    best_param = max(
        sensitivity.sensitivities.items(),
        key=lambda kv: abs(kv[1])
    )

    param_name, param_sensitivity = best_param
    required_delta = gap / param_sensitivity

    return FixSuggestion(
        parameter=param_name,
        direction="increase" if required_delta > 0 else "decrease",
        magnitude=abs(required_delta),
        expected_result=target,
        sensitivity_used=param_sensitivity,
        confidence="HIGH" if abs(param_sensitivity) > 0.1 else "MEDIUM"
    )
```

### 20.5.1 Uncertainty Propagation Through the Jacobian

**Problem:** If we know uncertainty in the physics outputs ($\sigma_{GM}$, $\sigma_R$), we should propagate it backward to quantify uncertainty in the suggested fix.

**Mathematical Basis:**

For a linear system $\mathbf{G} = \mathbf{J} \cdot \mathbf{p}$ where:
- $\mathbf{G}$ = physics outputs (GM, resistance, freeboard)
- $\mathbf{p}$ = geometry parameters (beam, draft, etc.)
- $\mathbf{J}$ = Jacobian (sensitivity matrix)

The suggested fix is:

$$\Delta \mathbf{p} = (\mathbf{J}^T \mathbf{J})^{-1} \mathbf{J}^T \Delta \mathbf{G}$$

The uncertainty in the suggested fix propagates as:

$$\sigma_{\Delta p}^2 = (\mathbf{J}^T \mathbf{J})^{-1} \mathbf{J}^T \cdot \text{diag}(\sigma_G^2) \cdot \mathbf{J} \cdot (\mathbf{J}^T \mathbf{J})^{-1}$$

**Implementation:**

```python
def suggest_fix_with_uncertainty(J: np.ndarray, G_target: np.ndarray,
                                  G_current: np.ndarray, sigma_G: np.ndarray
                                  ) -> FixSuggestionWithUncertainty:
    """
    Compute suggested geometry change with uncertainty bounds.

    Args:
        J: Jacobian matrix [n_outputs × n_params]
        G_target: Target physics values
        G_current: Current physics values
        sigma_G: Uncertainty in physics outputs

    Returns:
        delta_p: Suggested parameter change
        sigma_delta_p: Uncertainty in suggestion (±)
        leverage: Which parameter has most effect
    """
    delta_G = G_target - G_current

    # Pseudo-inverse solution
    JtJ = J.T @ J
    JtJ_inv = np.linalg.inv(JtJ)
    delta_p = JtJ_inv @ J.T @ delta_G

    # Propagate uncertainty
    sigma_G_diag = np.diag(sigma_G**2)
    cov_delta_p = JtJ_inv @ J.T @ sigma_G_diag @ J @ JtJ_inv
    sigma_delta_p = np.sqrt(np.diag(cov_delta_p))

    # Identify highest-leverage parameter
    leverage = np.abs(J).sum(axis=0)
    best_param_idx = np.argmax(leverage)

    return FixSuggestionWithUncertainty(
        delta_p=delta_p,
        sigma_delta_p=sigma_delta_p,
        leverage=leverage,
        best_param_idx=best_param_idx,
        confidence=compute_confidence(delta_p, sigma_delta_p)
    )


def compute_confidence(delta_p: np.ndarray, sigma_delta_p: np.ndarray) -> str:
    """
    Classify confidence based on signal-to-noise ratio.
    """
    snr = np.abs(delta_p) / (sigma_delta_p + 1e-10)
    min_snr = np.min(snr)

    if min_snr > 3.0:
        return "HIGH"    # Suggestion is 3σ from zero
    elif min_snr > 1.5:
        return "MEDIUM"  # Suggestion is 1.5σ from zero
    else:
        return "LOW"     # Suggestion may be within noise
```

```python
                 route_type: str,  # "access", "escape", "pipe", "cable"

        self.route_type = route_type
        self.waypoints = waypoints
        self.length = self.compute_length()

    def compute_length(self) -> float:
        total = 0
        for i in range(len(self.waypoints) - 1):
            total += distance(self.waypoints[i], self.waypoints[i+1])
        return total

    def check_clearance(self, obstacles: List[Volume]) -> bool:
        """
        Verify route doesn't intersect obstacles.
        """
        for segment in self.segments:
            for obstacle in obstacles:
                if segment.intersects(obstacle):
                    return False
        return True
```

## 22. Validation & Verification

### 22.1 Physics Gates vs Grades (Doctrine Aligned)

**CRITICAL DOCTRINE:** Only hydrostatics can set `status: INVALID`. Everything else is a grade.

**Gates (Can Set INVALID):**

| Gate | Condition | Failure Action |
|------|-----------|----------------|
| Volume closure | ∇ > 0 | Reject geometry with `INVALID` |
| Non-finite hydrostatics | All values finite | Reject geometry with `INVALID` |
| Solver convergence | Draft solver converges | Reject with `INVALID` |

**Grades (Can Set WARNING but NOT INVALID):**

| Grade | Condition | Warning Level | Action |
|-------|-----------|---------------|--------|
| Displacement balance | \|Δ - W\| < 2% | `MEDIUM` if violated | Iterate draft, return result |
| Initial stability | GM > 0 | `SEVERE` if violated | Return structured result with warning |
| Freeboard | D - T > 0 | `SEVERE` if violated | Return structured result with warning |
| Trim | \|trim\| < 2° | `MEDIUM` if violated | Iterate LCG, return result |

**Rationale:** An unstable design (GM < 0) is a valid physical object. It floats (until it capsizes). Blocking it as a gate prevents adversarial testing and novelty exploration.
